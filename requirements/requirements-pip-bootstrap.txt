# one of the "unsafe" packages (alongside setuptools and wheel) and drops it
# from --generate-hashes locks unless --allow-unsafe is passed, so it cannot
# live in requirements-lint.txt/-pytest.txt/etc. alongside the packages those
# actually pin.
#
# ci.yml's script-lint job and wheels.yml's test-the-wheel job each upgrade
# the venv's bootstrap pip to a known version before running their real
# --require-hashes install, and that upgrade step was itself unpinned by hash

# OSSF Scorecard's Pinned-Dependencies check flags (surfaced here as GitHub
# code scanning alerts #112 and #113). This file closes the gap: both jobs
# install pip via `--require-hashes -r requirements/requirements-pip-bootstrap.txt`
# instead. Bump the version and hashes here, in one place, when it needs to move.
#

# https://pypi.org/pypi/pip/24.3.1/json.
