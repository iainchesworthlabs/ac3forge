# Rust bindings

Two crates over [the C API](c-api.md), both in-tree under
[`rust/`](https://github.com/iainchesworthlabs/ac3forge/tree/main/rust):

- `ac3forge-sys`: raw FFI declarations, generated by `bindgen` from `ac3forge_c/ac3forge.h`. Its
  build script compiles the C library from the same checkout and regenerates the declarations at
  every build, so the two cannot drift apart.
- `ac3forge`: a safe wrapper with `Result` and `Option` in place of status codes and
  out-parameters, owned handles that free themselves on drop, and slices in place of raw pointers.

The crates cover the C API's scope: AC-3, E-AC-3 and Atmos (OAMD + JOC). They do not expose AC-4.
Neither the C header nor either crate names an AC-4 type or function, and the C API does not carry
the AC-4 libraries; [AC-4 decoding](ac4.md) describes the C++ library that decodes it.

Cargo is not part of the root CMake build, the same arrangement as `apps/android` and Gradle. CI
builds and tests the workspace on Linux, Windows and macOS (`build-rust` in
`.github/workflows/_build.yml`: `cargo build`, `cargo test`, `cargo clippy -D warnings`,
`cargo fmt --check`), against the toolchain pinned in `rust/rust-toolchain.toml`. Build
prerequisites (CMake, a C++23 compiler, libclang) and how the shared library is found at run time
are in
[`rust/README.md`](https://github.com/iainchesworthlabs/ac3forge/blob/main/rust/README.md).

```toml
[dependencies]
ac3forge = { path = "path/to/ac3forge/rust/ac3forge" }
```

## Encoding

Every config type calls the raw `ac3forge_*_config_init()` function through `Default::default()`
and lets you override only the fields you need, the `_init()` convention the C header documents.
The Rust side never restates a C++ default. `ObjectPlacement::default()` follows the same rule and
gives room centre, unity gain and no LFE send.

```rust
let config = EncoderConfig {
    sample_rate: SampleRate::Hz48000,
    bitrate_kbps: 192,
    acmod: Acmod::Stereo,
    ..Default::default()
};
let mut encoder = Encoder::new(&config).expect("failed to create AC-3 encoder");
```

That excerpt is from
[`rust/ac3forge/examples/encode_decode_ac3.rs`](https://github.com/iainchesworthlabs/ac3forge/blob/main/rust/ac3forge/examples/encode_decode_ac3.rs);
[`encode_decode_eac3.rs`](https://github.com/iainchesworthlabs/ac3forge/blob/main/rust/ac3forge/examples/encode_decode_eac3.rs)
is the E-AC-3 counterpart. Both run with `cargo run --example <name> -p ac3forge`.

## Decoding

`Decoder` and `Eac3Decoder` mirror `ac3forge_decoder_t` and `ac3forge_eac3_decoder_t`. Every
accessor on a `DecodedFrame`, `DecodedSubstream` or `DecodedAccessUnit` borrows from `&self`, so a
slice from `channel_samples()` cannot outlive the frame it came from. The compiler enforces the
"valid until destroyed" contract the C header states (see [C API](c-api.md#decoding)).

`Eac3Decoder::decode_substream` and `decode_access_unit` return `Result<Option<_>, Error>`. `None`
is not an error: transient pre-noise processing is holding that frame's PCM back, and `flush()`
collects it at the end of the stream. The C API reports the same case as `AC3FORGE_OK` with a null
out-parameter.

```rust
let decoded = decoder
    .decode_substream(&encoded)
    .expect("decode_substream failed")
    .expect("auto_tools without transient pre-noise never holds a frame back");
```

That excerpt is from `encode_decode_eac3.rs`.

## What is covered

| Module | Wraps |
|---|---|
| `ac3forge::ac3` | `Encoder`, `EncoderConfig` (including dual mono, DRC, heavy compression and the mix levels), `Decoder`, `DecodedFrame` |
| `ac3forge::eac3` | `Eac3Encoder`, `Eac3FrameConfig` (the Annex E tools through `auto_tools` or the individual flags; substream identity and `chanmap`), `Eac3FrameMetadata`, `AccessUnitEncoder` and `AccessUnit` for wide layouts built from several substreams, `Eac3Decoder` with `decode_substream`, `decode_access_unit` and `flush`, `DecodedSubstream`, `DecodedAccessUnit` |
| `ac3forge::atmos` | `AtmosEncoder`, `AtmosConfig`, `ObjectPlacement`; the OAMD and JOC accessors (`has_object_metadata`, `dynamic_object`, `object_audio` and their counts) on `DecodedSubstream` and `DecodedAccessUnit` |
| `ac3forge::stream` | `split_frames`, `split_access_units`, `stream_bsid`, `scan` and `ScannedStream` (kind, sample rate, layout, rendered channel count, each access unit's slice and sample count, `bsid`, the Atmos complexity index). The slices borrow the input buffer |
| `ac3forge::meter` | `LoudnessMeter` (the `acmod`/`lfe` constructor and the BS.1770-5 `chanmap` constructor) and `dialnorm_from_lkfs` |
| `ac3forge` | `Bytes` (an owned encoded buffer that derefs to `[u8]`), `Error`, `Latency` and the latency accessors on the encoders and decoders, `version()`, `SAMPLES_PER_FRAME` |

`ac3forge::Error` mirrors `ac3forge_status_t` and adds `Error::Other(u32)` for a status value this
crate does not know, so a newer library cannot make it panic or report the wrong error. It has no
variants for the scan errors (`AC3FORGE_ERROR_SCAN_*`); a failed `stream::scan` reports
`Error::Other` with the raw code.

Tests are in `rust/ac3forge/tests/`: round trips for every `acmod`/LFE combination, a wide-layout
5.1.2 encode and decode, Atmos objects round-tripped with their positions and audio, and the
stream and meter helpers.

## What is not wrapped

The raw `ac3forge-sys` crate declares every C function. The safe crate leaves these out, so
reaching them means calling `ac3forge_sys` directly:

- the caller-buffer decode forms (`ac3forge_decoder_decode_frame_into`,
  `ac3forge_eac3_decoder_decode_access_unit_into`);
- the level meter (`ac3forge_level_meter_*`) and the QC gates (`ac3forge_qc_*`,
  `ac3forge_evaluate_qc_gate`);
- the per-programme, timing and DVB/ATSC descriptor accessors of a scanned stream
  (`ac3forge_scanned_stream_programme_*`, `..._access_unit_timing`, `..._duration_*`,
  `..._associated_substream_*` and the raw `bsmod`, `dsurmod` and `channel_map` fields);
- the per-frame metadata words on decoded frames (`compr`, `dynrng`, the second channel's
  `dialnorm2`), a substream's `chanmap` and location map, the programme's bed and LFE flags, and
  a decoded access unit's layout;
- `ac3forge_latency_ms` and the bare sample-count latency functions (`Latency::total_samples()`
  sums the four terms instead).

The E-AC-3 config leaves out what the C struct leaves out, listed under
[What is deliberately out of scope](c-api.md#what-is-deliberately-out-of-scope). Scene files
(`ac3::oba::ObjectScene`) are not in the C API and so not here either.

## Notes for the next binding

Building this crate turned up four things about the C header, recorded in `rust/README.md`:

- `ac3forge_object_placement_t` had no `_init()`, unlike every other config struct, so a
  zero-initialized one encoded a muted object (`gain` 0.0) rather than the documented unity gain.
  `ac3forge_object_placement_init()` was added.
- Four decoded-audio accessors lacked the pointer-lifetime comment their AC-3 sibling has. It was
  added.
- bindgen types C enums as `i32` on MSVC and `u32` on the Unix targets, so a wrapper that stores a
  raw status must not assume either. `Error::Other` casts on the way in and out.
- The header does not say whether an enum may gain values in a later minor release. A binding
  should treat C enums as open sets, which is why `Error` has an `Other(u32)` variant.

Any binding should link `forge_c_shared`, which statically embeds the codec core, and should call
each `_config_init` function before overriding fields, since a zero-initialized struct is wrong for
several of them (`dialnorm` 0 is invalid).
